**Input**: Design documents from `specs/001-wasm-poc-setup/`
**Prerequisites**: plan.md, spec.md

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (e.g., US1)
- Include exact file paths in descriptions

---

## Phase 1: Project Setup

**Purpose**: Initialize the new Rust crate for the game and configure the basic web and build assets.

- [ ] T001 Initialize a new Rust binary project at the root of the repository named `starosta-game`.
- [ ] T002 Add `bevy` and `console_error_panic_hook` dependencies to `starosta-game/Cargo.toml`.
- [ ] T003 Create a `starosta-game/build.sh` script to compile the Rust code to WASM using `wasm-pack` and package it into a `dist/` directory.
- [ ] T004 [P] Create a basic `starosta-game/index.html` file to host the WASM application.

---

## Phase 2: Foundational Code

**Purpose**: Core Bevy application setup that MUST be complete before the main feature logic can be implemented.

- [ ] T005 In `starosta-game/src/main.rs`, set up the main Bevy application, add default plugins, and register a `GamePlugin`.
- [ ] T006 Create `starosta-game/src/lib.rs` and define the `GamePlugin` struct and its `Plugin` implementation.
- [ ] T007 In `starosta-game/src/lib.rs`, define an `AppState` enum with `Loading` and `Running` states and add it to the Bevy app configuration.
- [ ] T008 In `starosta-game/src/main.rs`, add the `console_error_panic_hook::set_once()` call, guarded by a `#[cfg(target_arch = "wasm32")]` attribute.

---

## Phase 3: User Story 1 - Build and Run PoC (Priority: P1) 🎯 MVP

**Goal**: To compile the Bevy application to WASM, have it load a graphical asset, and display that asset in a web browser.

**Independent Test**: Execute `build.sh`, start a static file server in the resulting `dist/` directory, and open the URL in a browser. The test passes if the specified image is visible.

### Implementation for User Story 1

- [ ] T009 [US1] Implement a `setup` system in `starosta-game/src/lib.rs` that is scheduled on app startup to begin loading the target image (`graphics/Spb.bmp`) via the `AssetServer`.
- [ ] T010 [US1] Create a system in `starosta-game/src/lib.rs` that monitors the asset loading progress and transitions the `AppState` from `Loading` to `Running` once the image is fully loaded.
- [ ] T011 [US1] Implement a system in `starosta-game/src/lib.rs` that runs once upon entering the `Running` state to set up a 2D camera.
- [ ] T012 [US1] Implement a system in `starosta-game/src/lib.rs` that also runs once upon entering the `Running` state to display the loaded image as a sprite on the screen.
- [ ] T013 [US1] Update `starosta-game/index.html` with the necessary JavaScript to fetch and instantiate the WASM module generated by `wasm-pack`.

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: Must be completed first.
- **Foundational (Phase 2)**: Depends on Setup completion.
- **User Story 1 (Phase 3)**: Depends on Foundational completion.
- **Polish (Phase 4)**: Depends on User Story 1 completion.

### Parallel Opportunities

- Within Phase 1, `T004` (creating `index.html`) can be done in parallel with the other Rust setup tasks.
- Within Phase 4, `T015` (commenting the build script) can be done in parallel with creating the README.
- The overall structure is highly sequential, as is typical for a foundational PoC.
